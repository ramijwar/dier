# بناء تطبيق خدمات الدير — Android Release ARM64

الملف `.github/workflows/build-apk.yml` يبني تطبيق Flutter الموجود في
`deir_app-source.zip` دون الحاجة إلى فك الضغط أو رفع ملفات المشروع يدوياً.

## التشغيل والتنزيل

1. ارفع التغييرات إلى GitHub. يعمل البناء تلقائياً عند رفع تعديل للأرشيف أو ملف الـworkflow.
2. أو افتح **Actions → Build Android Release ARM64 APK → Run workflow**.
   للتشغيل اليدوي يجب أن يكون ملف الـworkflow موجوداً على الفرع الافتراضي؛ بعدها يمكن اختيار فرع البناء.
3. اترك `flutter_version` فارغاً لاستخدام أحدث Flutter على قناة `stable`، أو أدخل إصداراً متوافقاً.
4. بعد نجاح التشغيل، حمّل `deir-services-release-arm64-v8a` من قسم **Artifacts**.
5. فك ضغط ملف التنزيل للحصول على `app-arm64-v8a-release.apk`.

يُحتفظ بملف التنزيل لمدة 14 يوماً. هذا APK للأجهزة ذات معمارية **ARM64 / arm64-v8a** فقط،
وليس لأجهزة ARM ذات 32 بت أو محاكيات x86_64.

## تفاصيل البناء

- يجهز الـworkflow Java 17 وAndroid SDK وFlutter، ثم يجلب حزم المشروع.
- يتطلب `pubspec.yaml` داخل الأرشيف **Dart >=3.13.4 و<4.0.0**؛ وتوصي تعليمات
  المشروع بـFlutter 3.47 أو أحدث. يجب أن يتضمن إصدار Flutter المختار نسخة Dart متوافقة؛
  إذا لم تكن متاحة على قناة stable فسيفشل جلب الحزم، ولا يخفض الـworkflow متطلبات المشروع تلقائياً.
- يعالج النسخة المستخرجة لإضافة Kotlin Android plugin المفقود، لأن إعدادات الأرشيف
  تعطل `android.builtInKotlin` بينما يستخدم التطبيق Kotlin. لا يغير الأرشيف الأصلي.
- أمر البناء:

  ```sh
  flutter build apk --release --target-platform android-arm64 --split-per-abi
  ```

## تنبيه التوقيع

البناء بوضع **Release**، لكن إعدادات المشروع الموجودة داخل الأرشيف تستخدم **مفتاح debug**
لتوقيع هذه النسخة. هذا مناسب للتجربة والتثبيت المباشر، وليس توقيع إصدار إنتاجي للنشر.
قد يتغير المفتاح بين تشغيلات GitHub Actions، ما يمنع تثبيت نسخة جديدة فوق القديمة.
للنشر والتحديثات المستقرة، يجب إعداد keystore خاص بالإصدار وربطه عبر GitHub Secrets؛
لا ترفع المفاتيح أو كلمات مرورها إلى المستودع.

لم يُنفذ بناء APK محلياً؛ يتطلب التحقق الكامل تشغيل الـworkflow على GitHub Actions.
